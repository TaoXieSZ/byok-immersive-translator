## Context

当前提取器把每个候选块压平成 `textContent`，批量通道返回 block ID 到字符串的 JSON 映射，流式通道返回单段文本增量，Content Script 最终只设置译文元素的 `textContent`。该链路避免了模型 HTML 注入，但无法表达截图中 `strong` 与多个行内 `code` 片段，也无法在目标语言调整语序后恢复对应格式。

格式保留横跨 DOM 提取、消息校验、Provider 提示词、流式显示、缓存和渲染。实现必须继续满足零运行时依赖、模型输出不可信、Content Script 无凭据、完整页面 HTML 不出站，以及首屏优先和会话取消不退化等约束。

## Goals / Non-Goals

**Goals:**

- 在译文中保留粗体、斜体、行内代码、键盘输入、标记、上下标、显式换行和安全链接等高价值行内语义。
- 给 Provider 保留完整句段上下文，并允许目标语言在保持格式归属的同时调整片段顺序。
- 只从原始 DOM 的可信描述构造译文节点，确保模型永远不能创建标签、属性、URL、样式或事件处理器。
- 让格式化块继续兼容批量通道、首段流式通道、canonical 去重、会话缓存、动态内容和恢复原文。
- 格式协议异常时保留可读译文并安全降级，不因格式丢失使整个批次失败。

**Non-Goals:**

- 不复制任意 `class`、内联样式、CSS 变量、脚本行为、组件状态或站点自定义元素。
- 不保留复杂块级布局、表格结构、图片、SVG、数学公式、代码块高亮或交互组件。
- 不让模型直接返回或执行 HTML，也不引入 HTML sanitizer 依赖。
- 不保证所有 Provider 都能稳定遵守格式标记；无法验证时以安全纯文本为准。

## Decisions

### 1. 从原始 DOM 建立受限格式模型

每个候选块除规范化文本外，保存一个版本化的格式描述。提取器按文本节点遍历，只识别 `strong/b`、`em/i`、`code`、`kbd`、`mark`、`sub`、`sup`、`br` 和 `a`；其他行内容器只展开其文本，不复制标签。每个受支持元素获得块内稳定 mark ID、语义类型和嵌套关系。

链接的目标地址、标题和安全属性只保留在 Content Script 的本地描述中，不发送给 Provider。渲染时仅接受原始节点中可解析为 `http:`、`https:`、`mailto:` 或同页 fragment 的链接；其他 scheme 降级为普通文本。新窗口链接强制补充 `rel="noopener noreferrer"`。

替代方案是克隆原始 `innerHTML` 后替换文本节点。它会携带任意属性、站点脚本挂钩和不可预测结构，安全边界过宽，因此不采用。

### 2. 使用扩展生成的成对不透明标记维持上下文和格式归属

格式化文本在发送前序列化为完整句段，并在受支持元素边界插入版本化、块内唯一的成对标记。Provider 仍翻译整段，可把完整标记对随目标语言语序移动，但不得修改、增加或拆分标记。普通纯文本块继续使用原协议，避免无格式页面增加负担。

共享解析器验证标记版本、ID 集合、每个标记恰好出现一次、开闭配对和合法嵌套。标记只表达对可信格式描述的引用，不携带标签名、属性或 URL。批量与非流式单段响应在完成后解析；流式响应先经过增量标记过滤器，只显示可确认的可见文本，完成时再原子替换为格式化 DOM。

替代方案是分别翻译每个文本节点。它容易破坏句子上下文和目标语言语序，并显著增加请求数，因此不采用。让模型返回 HTML 或 Markdown 同样因属性注入、解析歧义和站点样式污染而不采用。

### 3. 格式验证与翻译有效性分离

现有 block ID、批次完整性和字符串类型校验保持不变。格式解析是第二层校验：结构有效时生成格式化片段；结构无效时移除扩展保留标记并将剩余结果以 `textContent` 渲染，同时记录不含正文的 `format-fallback` 事件。未知或畸形的保留标记不得作为 DOM 指令解释。

如果响应本身缺少 block、包含未知 block 或不是字符串，仍沿用既有重试/失败策略。这样 Provider 只是格式遵循度不足时不会丢掉一段已经可读的翻译。

替代方案是格式标记错误即重新请求。它可能放大费用和延迟，而且同一模型可能重复犯错；安全纯文本回退更稳定。

### 4. 使用 DOM API 和白名单工厂重建译文

Content Script 创建新的译文容器与 `DocumentFragment`，普通内容使用 `Text` 节点，格式片段只通过固定工厂映射到 `strong`、`em`、`code`、`kbd`、`mark`、`sub`、`sup`、`br` 或经过检查的 `a`。模型字符串中的 `<script>`、Markdown 或其他标签始终是文本。

嵌套格式按已验证的标记栈构造。格式化结果只替换扩展自己的译文容器内容；原始 DOM、源链接和页面事件不被移动或修改。恢复原文继续删除整个译文容器和扩展状态标记。

### 5. 去重和缓存同时考虑文字与格式结构

canonical key 在规范化文本之外加入不含 URL 和正文的格式结构指纹。相同文字、相同语义结构的块可以共享一次翻译；相同文字但粗体、代码或链接分布不同的块必须分别处理。响应协议版本和格式模型版本进入 session cache key，旧的纯文本缓存自然失效。

缓存只保存完成且通过 block/格式校验的序列化译文，不保存原始 DOM、链接地址或未完成的流式片段。格式降级结果可以按明确的结果类型缓存，以避免重复请求，但不能被当作格式完整命中。

### 6. 保持首屏流式体验

无格式块维持当前逐 chunk 写入 `textContent`。格式化块的流式过滤器缓存可能构成标记的短尾部，立即输出确认不是标记的文本；标记本身不显示。收到完成事件后，解析完整结果并一次性升级为格式化 DOM。中断、取消或旧 session 的 chunk 仍按现有规则清理，未完成结果不进入缓存。

## Risks / Trade-offs

- [Provider 改写或遗漏不透明标记] → 严格验证后纯文本回退，记录结果类型，不执行猜测式 DOM 对齐。
- [目标语言需要把一个格式片段拆成多处] → 首版要求每个标记对完整移动，无法表达拆分时回退纯文本；优先保证语义和安全。
- [格式模型增加消息体积和解析成本] → 只为实际含受支持格式的块附加紧凑标记与指纹，并设置 mark 数量和序列化长度上限。
- [站点链接可能使用危险 scheme] → URL 不经过 Provider，渲染前按 scheme 白名单检查，失败时只保留文本。
- [流式标记跨 chunk 导致短暂延迟] → 仅缓冲最大标记长度的尾部，普通可见文本继续增量显示，完成后原子升级格式。
- [相同文本因格式差异降低去重率] → 这是避免错误套用格式的必要代价；无格式或相同结构块仍可去重。

## Migration Plan

1. 先补充格式提取、协议解析和安全渲染的纯函数测试，锁定现有纯文本路径。
2. 引入格式模型和共享验证器，但默认仍走纯文本渲染。
3. 接入批量、流式、缓存和 canonical key，启用格式化渲染与回退日志。
4. 在代表性 fixture 和真实技术文章上验证粗体、行内代码、链接、嵌套格式、停止和恢复原文。
5. 提升响应协议与缓存 schema 版本；旧 session 缓存自动 miss，无需迁移用户配置。

回滚时可关闭格式序列化和格式化渲染，保留原有纯文本协议；因未修改用户配置和原始 DOM，不需要数据回滚。
