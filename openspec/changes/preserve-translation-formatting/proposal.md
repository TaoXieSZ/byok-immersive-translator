## Why

当前译文以单个纯文本节点渲染，虽然安全，但会丢失原文中的粗体、斜体、行内代码、链接和上下标等阅读语义。技术文章中这些格式承担标题强调、标识符边界和可点击引用等关键信息，格式丢失会明显降低双语阅读质量。

## What Changes

- 提取文本块时同时建立只包含受支持行内语义的格式模型，并保留完整上下文供 Provider 翻译。
- 扩展翻译协议，使返回结果能够把译文片段与原文格式语义稳定关联；格式标记缺失、重复、未知或结构不合法时不得猜测。
- 使用 DOM API 从受信任的格式模型重建译文，只允许粗体、斜体、行内代码、键盘输入、标记、上下标、换行和安全链接等白名单结构。
- 链接地址和安全属性只从原始页面节点复制，模型不能提供标签、属性、URL、样式或事件处理器；任何模型 HTML 仍作为普通文本处理。
- 对无法可靠对齐、包含不支持结构或 Provider 未遵守格式协议的块回退到已验证的纯文本译文，避免格式问题阻塞翻译。
- 将格式结构指纹纳入去重和缓存语义，避免相同文字但不同格式的块错误共享渲染结果。
- 为嵌套格式、重复文本、链接安全、格式重排、流式与批量响应、无效结构回退以及恢复原文补充自动化测试。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `immersive-page-translation`: 译文从始终为单个纯文本节点，升级为在安全白名单和严格验证下保留原文的行内格式语义，并在无法可靠保留时安全回退到纯文本。

## Impact

- 影响 Content Script 的候选块提取、canonical 去重、译文渲染、动态内容观察和恢复原文逻辑。
- 影响 Content Script 与 Service Worker 之间的翻译消息、OpenAI-compatible 请求/响应校验、流式首段协议和会话缓存键版本。
- 更新 `immersive-page-translation` 规格及相关提取、协议、适配器、缓存、编排和 DOM 渲染测试。
- 不增加运行时依赖，不扩大浏览器权限，不向 Content Script 暴露凭据，也不允许远端输出直接成为 HTML。
