## ADDED Requirements

### Requirement: 首屏极速通道与后台吞吐通道
扩展 SHALL 在翻译启动后立即为当前视口候选块创建 loading 状态，并 MUST 将首个尚未命中的可见文本块通过支持流式响应的单段极速通道优先提交。扩展 SHALL 同时在后台渐进提取和批量翻译其余候选块，且极速通道不得等待整页提取完成。

#### Scenario: 冷启动翻译当前视口
- **WHEN** 用户在包含多个可翻译段落的页面启动翻译且首段没有缓存
- **THEN** 当前视口候选块先显示 loading，首个可见块通过极速通道提交，其余块由后台吞吐通道继续处理

#### Scenario: Provider 不支持流式响应
- **WHEN** 当前 provider 的性能能力声明不支持可靠的 Chat Completions 流式响应
- **THEN** 扩展使用单段非流式极速请求，并继续使用批量后台通道而不阻塞整个 session

#### Scenario: 流式请求中途失败
- **WHEN** 极速通道已经收到部分 token 后发生网络错误或响应格式错误
- **THEN** 扩展不缓存或确认部分译文，保留原文并按失败策略回退到一次非流式单段重试

### Requirement: 渐进提取与阅读位置重排
扩展 MUST 先提取当前视口及主要内容区域，再以不会长时间阻塞主线程的分片方式发现页面其余候选块。活动 session SHALL 在用户滚动后重新计算尚未提交块的优先级，使新进入视口的内容先于屏外积压内容处理，已提交请求不得因重排重复发送。

#### Scenario: 长文章首次启动
- **WHEN** 页面包含大量候选块
- **THEN** 扩展先完成当前视口发现和调度，并分片提取页面其余内容而不等待一次同步整页扫描

#### Scenario: 用户滚动到未翻译区域
- **WHEN** 活动 session 中用户滚动使排队块进入视口
- **THEN** 扩展在下一次调度时提升这些块的优先级且不重复提交已处理块

### Requirement: 会话缓存、目标语言跳过与相同文本去重
扩展 MUST 在提交请求前跳过已主要使用目标语言的候选文本，并 MUST 在同一页面内将相同规范化原文只提交一次后把已验证译文分发到所有对应块。扩展 SHALL 默认使用仅限当前浏览器会话的缓存复用已验证译文，缓存键 MUST 至少包含 provider ID、模型、目标语言、提示词版本、响应协议版本和规范化原文哈希，且不得默认持久保存网页正文或未完成译文。

#### Scenario: 页面包含重复导航文本
- **WHEN** 多个候选块具有相同规范化原文和相同翻译上下文
- **THEN** 扩展只向 provider 提交一次并把同一已验证译文安全渲染到所有对应块

#### Scenario: 文本已是目标语言
- **WHEN** 候选文本被语言判定器识别为主要使用目标语言
- **THEN** 扩展不创建远端翻译请求且不插入冗余译文

#### Scenario: 当前会话命中缓存
- **WHEN** 相同缓存键已经保存一条完整且已验证的译文
- **THEN** 扩展直接渲染缓存译文而不向 provider 发出请求

#### Scenario: 浏览器会话结束
- **WHEN** 浏览器会话结束或扩展会话存储被清除
- **THEN** 默认翻译缓存随之失效且磁盘上不保留可还原的网页正文

### Requirement: Provider 自适应并发与过载恢复
Service Worker MUST 作为所有翻译请求的唯一并发控制边界，并 SHALL 根据选中 provider 的性能画像设置初始、最小和最大并发。调度器 MUST 在收到 429、503 或连续高延迟时降低并发并按带抖动退避重试，在连续成功后逐级恢复，但不得超过 provider 最大并发或继续提交已停止 session 的请求。

#### Scenario: DeepSeek 正常响应
- **WHEN** DeepSeek 性能画像处于默认状态且请求连续成功
- **THEN** 调度器从该画像的初始并发运行并在满足恢复阈值后逐级提升且不超过最大并发

#### Scenario: Provider 返回限流
- **WHEN** 任一翻译请求返回 429 或 503
- **THEN** 调度器降低该 provider 的当前并发、按 Retry-After 或带抖动退避后重试，并保持其他已成功译文

#### Scenario: 自定义 Provider 没有性能声明
- **WHEN** 用户选择没有明确流式或限流能力的 OpenAI-compatible provider
- **THEN** 扩展使用保守非流式能力和保守初始并发，直到可观测成功结果允许有限提速

#### Scenario: 用户停止活动 session
- **WHEN** 用户在等待 permit、退避或请求期间停止翻译
- **THEN** 调度器取消该 session 的活动请求并移除其等待任务，不再消耗后续 permit

### Requirement: 可量化性能预算与安全遥测
扩展 MUST 使用单调时钟记录点击、loading 插入、首个请求、首个 token、视口完成、全页完成、缓存命中和并发降速事件。结构化日志 MUST 包含 session ID、通道、批次或块索引、耗时和结果类型，但 MUST NOT 包含 API Key、完整原文或完整译文。自动化基准 MUST 将扩展调度耗时与 provider 网络耗时分开报告。

#### Scenario: 受控冷启动基准
- **WHEN** 在 122 块代表性长文章 fixture 和确定性流式 provider stub 上运行性能验收
- **THEN** 点击后 100ms 内出现首批 loading、200ms 内发出首个请求、2.5s 内显示首个译文 token、5s 内完成初始视口，且整页翻译请求不超过 8 个

#### Scenario: 缓存命中基准
- **WHEN** 初始视口所有候选块都命中当前会话缓存
- **THEN** 点击后 300ms 内完成初始视口渲染且不发出远端翻译请求

#### Scenario: 查看性能日志
- **WHEN** 开发者检查一次完成或失败的翻译 session
- **THEN** 日志可以区分扩展排队、提取、网络首 token 和 provider 完成耗时且不泄露页面正文或凭据
