## Context

扩展目前只有“主要内容”和“整个页面”两种翻译范围。Content Script 管理长生命周期的整页 session，Service Worker 使用当前选中的 Provider 完成批量或单块流式翻译，并按 Provider、模型、语言、Prompt 和格式指纹缓存验证后的结果。

段落魔法镜需要服务短生命周期、用户明确触发的划词翻译。它必须在不修改原始 DOM、不影响整页 session、不暴露 Provider 凭据的前提下，利用所在语义段落改善短语消歧，并在页面选择、滚动和响应迟到时保持可预测。

## Goals / Non-Goals

**Goals:**

- 对普通网页中的有效选区显示低干扰入口，且只在用户点击入口后消耗 API。
- 翻译选中文字，同时只把有上限的纯文本语义段落作为消歧上下文。
- 复用当前选中 Provider、调度器、错误分类和流式适配器，但保持独立请求生命周期。
- 用独立缓存维度避免不同上下文或整页翻译结果发生错误复用。
- 提供响应迅速、可关闭、可复制、可重新翻译且适应视口边缘的 Shadow DOM 卡片。

**Non-Goals:**

- 不在第一版提供解释、朗读、收藏、术语编辑、多 Provider 对比或自动替换正文。
- 不支持输入框、`contenteditable`、`pre`、`code`、扩展生成译文、跨复杂编辑根或浏览器限制页面。
- 不增加无按键悬停翻译、自动选区请求、PDF、字幕、OCR 或移动端专用手势。
- 不硬编码 `agent` 等术语的字符串替换；选区翻译遵循统一 Prompt 语义。

## Decisions

### 1. 选区检测与远端请求分成两个显式阶段

Content Script 增加独立的 magic-lens controller。它在指针或键盘选区稳定后读取 `Selection`/`Range`，验证文本与祖先元素，再于选区末端附近展示小按钮。选区必须包含有意义字符，规范化后长度为 1 至 2000 个字符，并位于单一受支持的页面内容根中。

检测阶段只在本地保存临时快照，不发送消息。用户点击按钮时才固定该快照、生成 `requestId` 并打开卡片。这比“选择后立即翻译”更能控制 Token 和隐私，也避免拖选过程产生重复请求。

替代方案：直接在现有整页 session 中创建临时 block。拒绝该方案，因为恢复原文、停止 session、进度统计和 MutationObserver 都不应拥有魔法镜卡片。

### 2. 上下文是有界纯文本，选区是唯一输出目标

controller 从最近的受支持语义容器提取规范化 `textContent`，最多保留 4000 个字符作为 `contextText`；若找不到安全容器，则退化为选区本身。请求分别携带 `selectionText` 和 `contextText`，不携带 DOM、HTML、URL、样式、属性、Cookie、表单值或相邻段落。

Service Worker 构造专用 Prompt，明确要求只返回 `selectionText` 的译文，`contextText` 仅用于词义和指代消歧。输出按纯文本处理，不恢复或执行模型 HTML。

替代方案：发送完整页面标题、摘要或前后段落。拒绝该方案，因为第一版的质量收益不足以抵消隐私边界和请求体积增长。

### 3. 新的严格选区协议复用可信后台所有权

共享协议增加选区开始、流式片段、完成、错误和取消消息。开始消息只允许 `requestId`、目标语言、选中文字、上下文和布尔型 `bypassCache`，并对键集合、长度和标识符做白名单校验。Content Script 仍不能指定 Provider ID、Base URL、模型、请求头、并发或重试策略。

Service Worker 始终读取当前已保存 Provider，将 `requestId` 作为调度和取消作用域。卡片关闭、新选区或页面生命周期结束时发送取消；即使底层传输来不及终止，Content Script 也通过当前 `requestId` 丢弃迟到消息。

### 4. 选区缓存显式包含上下文语义

选区缓存键使用独立的 mode/schema，并包含 Provider ID、模型、目标语言、选区 Prompt 版本、`selectionText` 哈希和 `contextText` 哈希。缓存值只保存完成且验证后的译文、时间和安全元数据，不保存选区或上下文明文。

“重新翻译”发送 `bypassCache: true` 并原子替换当前卡片结果。绕过缓存不会删除旧条目；新结果验证完成后可覆盖相同键。整页缓存不会自动满足选区请求，除非未来另行设计经过证明的兼容映射。

### 5. 卡片是独立、单实例、可访问的状态机

页面内同时最多存在一个 trigger/card host，并使用 closed Shadow DOM 隔离样式。状态为 `hidden → trigger → loading → streaming → complete | error`。点击后立即进入 loading；缓存命中目标为 300ms 内完成；支持流式 Provider 时逐步展示安全纯文本。

卡片锚定选区最后一个非空 client rect，并在滚动或窗口尺寸变化时通过 `requestAnimationFrame` 重新定位、限制在视口安全边距内。新选区、外部点击、`Esc`、关闭或页面隐藏会关闭卡片。控件使用原生 button、可见焦点、状态文案和 `aria-live`；复制只在用户点击时调用 Clipboard API，失败时留在卡片中反馈。

### 6. 与整页翻译保持正交

魔法镜不写入 `currentSession.blocks`，不改变整页范围、进度、停止、重试或恢复原文。整页翻译可以在卡片存在时继续运行；魔法镜取消也不得取消整页调度任务。任何位于 `[data-byok-translator]` 或魔法镜 host 内的选区均被排除，防止目标语言重复翻译。

## Risks / Trade-offs

- [选区横跨多个复杂容器时上下文含义不稳定] → 第一版拒绝无法归属单一安全内容根的选区，并保持入口不出现。
- [长段落上下文可能截断关键消歧信息] → 采用确定性的 4000 字符上限并优先保留覆盖选区的窗口，测试边界位置。
- [网站通过极高 `z-index`、transform 或裁剪影响位置] → host 固定在文档根并使用视口坐标、最高安全层级和 Shadow DOM；极端站点允许关闭而不修改网页。
- [重新翻译可能被恶意页面诱导增加费用] → 远端请求仍需真实扩展按钮点击，Content Script 不接收页面 `postMessage` 命令，后台保留并发与取消限制。
- [键盘选区与焦点移动可能造成卡片抢焦点] → trigger 不自动聚焦；用户显式进入卡片后才在卡片控件内导航，`Esc` 返回页面。
- [缓存上下文哈希降低命中率] → 优先保证语义正确；规范化空白后再哈希，避免纯排版差异破坏命中。

## Migration Plan

1. 先增加共享协议、纯函数选区验证和选区缓存键，不注册页面监听器。
2. 增加后台选区翻译与取消处理，并用测试确认凭据、错误和调度边界。
3. 增加 Content Script controller 与 Shadow DOM 卡片，再接入扩展启动流程。
4. 在普通文章真实网站验证选择、滚动、暗色背景、缓存、错误和整页翻译共存。
5. 如需回滚，移除 controller 注册和选区消息处理即可；现有整页协议与缓存 schema 不变。
