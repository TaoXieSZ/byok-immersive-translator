## Why

当前悬浮按钮仍需先通过浏览器扩展 Popup 注入，单击后只会展开控制面板；翻译流程还必须等待整页扫描和非流式批次全部返回，首段反馈与整页吞吐均明显落后于成熟产品。现在需要把“开始翻译”压缩为真正的一次页面内点击，并以可量化指标重构冷启动、首屏和重复访问速度。

## What Changes

- 让悬浮按钮在空闲状态下单击即开始翻译，页面已有译文时再次单击即停止当前会话并恢复原文，同时取消启动后自动弹出大面板。
- 提供一次性、可解释的可选网站访问授权；授权后持久注册页面控制器，重启浏览器后仍自动显示悬浮按钮，拒绝授权时保留现有 `activeTab` 手动注入模式。
- 将翻译调度拆分为首屏极速通道和后台吞吐通道：当前视口优先发出单段流式请求，整页扫描、批处理和 loading 节点在后台分片进行。
- 对待处理内容进行目标语言跳过、相同文本去重和滚动后动态重排，避免把带宽和模型时间浪费在用户未阅读或无需翻译的内容上。
- 增加默认仅限浏览器会话的翻译缓存；相同 Provider、模型、目标语言和原文可立即复用，且不默认持久保存网页正文。
- 为 Provider 引入性能能力与自适应并发：DeepSeek 使用较高初始并发和流式能力，自定义 OpenAI-compatible Provider 使用保守默认值，并在 429、超载或高延迟时自动降速。
- 将 DeepSeek 新建配置默认模型更新为当前快速非思考模型，同时兼容用户已有模型配置。
- 增加点击到 loading、点击到请求、首段出字、首屏完成、全页完成、缓存命中和 429 降速等性能度量及自动化基准。
- 增加快捷键切换与“主要内容/整个页面”翻译模式，为后续悬停段落翻译和站点规则保留清晰扩展点。

## Capabilities

### New Capabilities

- `translation-performance`: 规定首屏流式通道、后台自适应调度、会话缓存、文本去重、性能指标和降速恢复行为。

### Modified Capabilities

- `immersive-page-translation`: 增加真正的一键悬浮入口、可选持久注入、主要内容模式、滚动重排和快捷键交互要求。
- `byok-provider-configuration`: 增加 Provider 性能能力、并发策略和 DeepSeek 当前快速模型预设要求。

## Impact

- 影响 Manifest 权限声明、Service Worker 启动与动态 Content Script 注册、Options 首次授权体验、悬浮控制器状态机、页面文本提取、翻译批次协议、OpenAI-compatible adapter、缓存和结构化日志。
- 翻译消息需要支持流式单段与批量 JSON 两种响应路径，同时保持 session ID、迟到响应丢弃、取消和纯文本渲染安全边界。
- 不增加运行时第三方依赖，不引入远程托管代码，不向 Content Script 暴露 API Key，也不默认把网页正文持久写入磁盘。
- 需要扩展 Node 编排测试、消息验证测试和浏览器性能验收；现有 Provider 配置与 `activeTab` 使用方式保持兼容。
